# 校园诉求标签、紧急度与部门标准

更新日期：2026-10-06。本文档是当前统一标注标准；数据、模型接口和规则代码均应以此为准。

## 字段标准

所有数据、代码和接口统一使用 `label` 表示诉求类别。不得再新增 `category` 字段。读取旧文件时可以将 `category` 兼容转换为 `label`，但输出必须使用 `label`。

正式数据字段固定为：

```text
text,label,urgency,department
```

## 类别与责任部门

| label | 默认责任部门 |
| --- | --- |
| 宿舍设施 | 慧湖物业中心 |
| 校园网络 | 网络管理部 |
| 食堂餐饮 | 餐饮管理 |
| 教学设施 | 教学保障 |
| 校园安全 | 保卫处 |
| 其他 | 人工处理 |

## 六类标签边界

### 宿舍设施

宿舍房间、走廊、洗衣房、卫生间及宿舍生活配套设施的问题，包括门锁、衣柜、空调、热水、照明、插座、洗衣机和宿舍宽带。

本校宿舍位于校区外，使用自有宽带而不是校园网。因此宿舍内断网、宿舍宽带故障和宿舍网络认证问题统一标为：

```text
label=宿舍设施
department=慧湖物业中心
```

### 校园网络

校内教学楼、图书馆、机房等区域的校园网、无线网络、VPN、统一认证及依赖网络访问的平台故障。

教务系统、教学平台等业务名称本身不决定类别。如果核心问题是校园网连接、认证或大范围网络中断，标为校园网络；如果软件或设备脱离网络后仍然故障，则根据实际对象标为教学设施或其他。

### 食堂餐饮

食堂饭菜、食品卫生、菜品选择、价格扣费、档口服务、餐具、排队及餐饮设备使用问题。

饭菜导致人员出现腹痛、呕吐、腹泻、恶心、发热或实际过敏反应时，仍标为食堂餐饮，但紧急度必须为高。

食堂场所内的明火、冒烟、漏电、燃气泄漏、危险坠物等直接公共安全风险，主类别标为校园安全，不因发生地点在食堂就标为食堂餐饮。

### 教学设施

教室、实验室、自习室中的投影仪、扩音器、电脑、实验软件、白板、桌椅、插座、空调等教学设备或环境设施问题。

出现“教室”“教学楼”“实验楼”等地点词，不代表一定属于教学设施。通知、失物招领、材料审核、办事流程等问题仍应根据实际诉求标为其他。

### 校园安全

火情、冒烟、漏电、裸露电线、燃气泄漏、暴力威胁、危险交通、消防通道堵塞、坠物风险及其他可能造成人身伤害的校园公共安全问题。

当一个设施故障已经形成直接人身危险时，按更紧急的安全问题确定主类别。例如食堂微波炉着火、教学楼电线冒火花，应标为校园安全。

宿舍内部设施虽然可能存在安全风险，但当前固定业务映射仍允许根据主要处置对象标为宿舍设施，例如宿舍插座电线裸露、被子被锁在外面。标注时应结合既有数据标准保持一致。

### 其他

不属于上述五类的校务和校园生活诉求，包括失物招领、通知发布、证明与材料办理、奖学金、校园卡服务、活动审批、班车、快递和一般咨询。

不能因为文本出现“教学楼”“教室”“图书馆”等地点词，就将此类诉求误标为教学设施。

## 紧急度规则

- 高：文本描述了对师生人身安全或健康的现实威胁，需要立即响应。
- 中：明显影响正常学习生活，但尚无直接人身安全或健康威胁。
- 低：一般建议、体验优化或不影响基本使用的问题。

以下情况必须标为高：

- 火情、冒烟、漏电、裸露电线、燃气泄漏、暴力威胁、危险坠物等直接人身安全风险。
- 明确疾病、受伤、严重过敏或其他师生健康风险。
- 食堂或食品问题已经导致任何人数出现身体症状，无论是一人还是多人。
- 缺少基本生活保护条件，例如夜间没有被子可盖。
- 选课等具有明确办理时限、并会影响后续学习安排的关键业务发生实际故障。
- 全校、多个教学楼、整栋楼等大范围关键服务中断。

一般设施或服务无法使用，但没有直接安全健康风险、大范围影响或紧迫办理期限时，通常标为中。

建议增加服务、改善体验、补充耗材、优化标识等未影响基本使用的问题，通常标为低。

必须结合完整语义判断。以下情况不因出现危险词就自动判高：

- 否定表达，例如“没有漏电，只是盖板松动”。
- 只提出预防建议，但没有描述当前威胁。
- 描述动物受伤，但没有师生安全或健康风险。

例如“希望食堂标明花生等过敏原”属于预防建议；如果没有人实际出现过敏反应，不因出现“过敏原”而自动判高。

## 宿舍被子示例

```text
text=被子被锁在外面，晚上没有被子盖
label=宿舍设施
urgency=高
department=慧湖物业中心
```

该情况会使学生缺少基本御寒条件，属于明确健康风险，因此标为高。

## 多问题规则

同时出现多个类别时，以紧急程度更高的问题确定主类别。若紧急程度相同，选择主要诉求或最需要立即处理的问题对应的类别。

例如：

```text
食堂微波炉着火
→ 校园安全,高,保卫处

食堂微波炉不能加热
→ 食堂餐饮,中,餐饮管理
```

## 已确认的边界案例

```text
宿舍宽带断网
→ 宿舍设施,中,慧湖物业中心

教务系统选课时一直加载失败
→ 校园网络,高,网络管理部

实验室部分电脑无法启动实验软件
→ 教学设施,中,教学保障

一名同学在食堂就餐后出现腹痛和呕吐
→ 食堂餐饮,高,餐饮管理

希望食堂标注花生等过敏原
→ 食堂餐饮,低,餐饮管理

在教学楼捡到学生卡，询问交到哪里
→ 其他,低,人工处理

食堂微波炉冒烟并出现火花
→ 校园安全,高,保卫处
```

## 标注检查顺序

1. 先判断文本真正要解决的问题，不按地点词直接分类。
2. 若同时存在多个问题，先判断哪个问题更紧急，并以其作为主类别。
3. 根据完整语义确定高、中、低，特别检查否定表达和是否已经产生现实风险。
4. 根据最终 `label` 填写固定责任部门。
5. 最终确认四个字段齐全，且只使用 `label`，不新增 `category`。
